# 表格布局与内容整合

## 表格宽度与对齐

先区分表格整体位置、单元格水平对齐和垂直对齐。用户要求表格居中时，同时检查表宽；超出正文区域的表格仅设居中仍会溢出。表头和数值列通常适合居中，长说明按阅读需要保留左对齐，用户明确指定的对齐方式优先。

对普通单栏、固定 dxa 列宽的矩形表格，从所在 Section 读取 `pgSz.w - pgMar.left - pgMar.right`，再核对每行 `tcW.w` 总和。列宽按内容分配，保留原有表格、行列及每格文字；嵌套、合并单元格、百分比宽度或多栏布局需要另查实际可用区域，不能套用同一计算。

当前已验证 SDK 调用：

- 先用 `selection.setRange(begin,end)` 选中已核验的单元格文字，再从 `selection.getTableSelectionService()` 取得服务，核对 `getSelectedTable().getRange()`。任意 `doc.getRange(...).getTableSelectionService()` 不一定已绑定表格。
- 整体居中用 `setTableHorizonAlignment(sdk.STJcTable.center)`；单元格文字用 `selection.getParagraphFormat().setParagraphAlignment(sdk.STJcWml.center)`，两种枚举不能混用。垂直居中用表格服务的 `setVerticalAlign(2)`。
- 普通矩形表格可对 `table.rows[].cells[]` 调用 `cell.setWidth(widthTwips)`，再用该表格服务的 `tableAlignService.applyTableUpdate()` 提交。内部方法先核对当前实例的实现；提交后重新取得服务再做下一项操作。

回读核对所有行的列宽、`tblPr.jc`、每格 Paragraph 的 `jc` 与 Cell 的 `vAlign`。某些默认属性可能被省略，需结合继承样式或编辑器有效属性判断，不能一律把属性缺失当作不匹配。结构核验不代替视觉验收。

## 原生文字与范围

GCP 范围和表达式长度按 UTF-16 单元计算；Python 的 `len(text)` 对非 BMP 字符不等于 GCP 长度。使用原生节点范围，并与编辑器 `doc.readText(begin,length)` 比较。

超链接字段的原生文字包含 `\x13`、字段指令、`\x14`、显示文字、`\x15`。只拼接 Text 节点会漏掉字段控制字符，显示文字也不能替代完整字段。重建原文时识别 Run 的 `meta.field.type`（begin/code/separate/result/end），保留字段指令和标记；只改链接所在段落的间距时，可选中该段普通文字来设置段落属性。

`getTextStream().getLength()` 可能包含正文之外的子故事，不能与主正文结束 GCP 直接比较。按实际主故事范围核验正文；若以完整文字池做逐次替换校验，就保存整个文字池并同步计算预期变化，不把两种长度混用。

## 段落合并与表前标记

内容整合先建立旧段落到新段落的映射，保留事实、数值、限定条件、版本与链接。合并重复说明和过碎的小节时，同步更新标题层级、编号和内部引用。目标外内容保持原位；含原生字段的段落优先保留字段节点。

从后向前处理已核验的范围。每次替换前比较准确原文，替换后比较预期全文或完整目标及外围内容；不匹配即停止后续写入。记录当前操作、阶段和已完成项，回读后只生成尚未完成的动作。

普通段落的 `end` 包含 `\r`。表格前存在必需的段落结束标记；删除紧邻表格的整个段落时，编辑器可能保留一个 `\r`，产生空段落。处理同一主故事内连续普通段落时：

- 合并后仍保留前一段、删除末尾表前说明：可删除 `[保留末段.end - 1, 被删末段.end - 1)`，保留紧邻表格的结束标记，再替换保留段的文字。
- 表前已经只剩一个多余空段落：在确认前一段为普通段落且两者相邻后，删除前一段的结束符，使前文使用表格前保留的结束标记。
- 删除前核对范围内的准确原文及 `\r`，确认不包含表格、字段或其他结构标记；删除后核对前文、表格内容和新范围。跨表格或子故事的范围不适用上述方法。

逐段替换文字时保留段落结束符，按新段落角色设置正文或标题样式。标题层级从现有 `pStyle` 和 styles 定义确定，不以可见编号直接猜 `Heading1/Heading2`。

## 行内样式

段落角色与行内强调分开处理。合并前记录目标段落内保留片段的有效粗体、斜体、下划线、颜色等样式，以及链接字段；将这些片段映射到新段落中的准确范围。改写后不再保留的短标签不需要机械迁移强调，仍保留的并列标签则应保持一致。

设置 Normal/Heading 样式或对整段调用 `setBold(false)` 等操作可能清除原有行内样式。先完成段落和基础字体设置，再对明确映射的片段恢复强调；整段取消加粗只适用于目标确实是全段普通正文的情况。

写后逐项检查新范围中的 Run 属性与相邻并列项，允许 Run 分裂或合并。核验包含标签本身和其后普通正文，避免只恢复整段加粗。全文文字、字体或字号核验通过不能替代这项检查。

## 列表层级

去掉上级说明或把嵌套项合并为一级项时，重新创建列表可能沿用旧 `ilvl`。目标为一级列表时，先对准确范围调用 `numbering.cancelListInRange(range,false)`，清理残留左缩进、首行及悬挂缩进，再用已验证的 `createListInRange` 创建列表。

回读确认 `numPr.ilvl`、numbering 类型及有效缩进；仅看到新 numId 不代表层级已改变。列表整理后仍核对标签的行内加粗与正文样式。
